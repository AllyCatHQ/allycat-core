# CSS Delivery Methods — Full Scan Support Status

> Applies to **full scan only** (Playwright + Chromium).
> Quick scan intentionally skips CSS — JSDOM cannot compute layout or contrast, so contrast rules are disabled there by design.

---

## Currently Supported

| Method | Example | Notes |
|---|---|---|
| `<link rel="stylesheet" href="...">` in HTML | `<link rel="stylesheet" href="./styles.css">` | Extracted and injected as `<style>` block |
| `<style>` block already in HTML | `<style>.btn { color: red; }</style>` | Preserved natively by Playwright |
| `style=""` inline attribute | `<div style="color: red;">` | Preserved natively |
| `import './style.css'` (side-effect) in JSX/TSX | `import './Button.css'` | Extracted from source, injected |
| Relative paths | `./theme.css`, `../../global.css` | Resolved from source file directory |
| Standard aliases | `@/`, `@styles/`, `@assets/`, `@css/` | Hardcoded alias map in `cssResolver.js` |
| CSS cache (shared per scan run) | — | Each file read from disk only once |
| **Vue `<style>` block** | `<style>.btn { color: red; }</style>` | `extractStyleBlocks()` in `vueTransformer.js` |
| **Vue `<style scoped>` block** | `<style scoped>.btn { color: red; }</style>` | Same — `scoped` attribute does not affect extraction |
| **Angular `styleUrls`** | `styleUrls: ['./comp.css']` | `extractStyleUrls()` in `angularTsExtractor.js`, resolved via `resolveCssPaths()` |
| **Angular `styles[]` inline array** | `styles: ['.btn { color: red; }']` | `extractInlineStyles()` in `angularTsExtractor.js` — bracket-depth scanner handles attribute selectors |
| **Transitive `@import` inside CSS files** | `@import './colors.css';` inside an already-loaded `.css` file | `extractTransitiveCssImports()` in `cssResolver.js` — recursive with O(1) cycle guard |
| **CSS Modules — Vue `<style module>`** | `:class="$style['name']"` | `tryExtractStyleModuleClass()` in `vueTransformer.js` — extracts literal class name from `$style[]` binding |
| **CSS Modules — JSX/TSX** | `import s from './Button.module.css'` → `className={s.primary}` | `extractCssModuleBindings()` + `resolveCssModuleClass()` in `jsxTransformer.js` |
| **CSS Modules — Angular** | `import styles from '*.module.css'` → `[class]="styles.prop"` | `extractCssModuleImports()` in `angularTsExtractor.js`; resolves dot and bracket notation |
| **npm package CSS** | `import 'bootstrap/dist/css/bootstrap.min.css'` | `resolveNodeModulesCss()` in `cssResolver.js` — checks `<sourceDir>/node_modules/` then `<projectRoot>/node_modules/` |
| **Custom aliases (tsconfig.json)** | `@test-theme/colors.css` | `loadTsconfigAliases()` reads `compilerOptions.paths` once per scan run |
| **`<link media="print">` filtering** | `<link rel="stylesheet" media="print" href="print.css">` | Print stylesheets skipped — `media=["']print["']` guard in `extractCssLinkHrefs()` |

## Not Supported — CSS-in-JS (JSX/TSX)

| Method | Example | Status |
|---|---|---|
| Styled Components | `` styled.button`color: red;` `` | ❌ Out of scope — see below |
| Emotion (`@emotion/react`, `@emotion/styled`, `@emotion/css`) | `` css`color: red;` `` | ❌ Out of scope — see below |
| styled-jsx (`styled-jsx/css`) | `` css`color: red;` `` | ❌ Out of scope — Next.js built-in |
| Stitches (`@stitches/react`) | `styled('div', { color: 'red' })` | ❌ Out of scope — runtime CSS-in-JS |

**Why CSS-in-JS cannot be supported:**

Runtime-evaluated CSS. Styles do not exist in any file or import path — they are generated by executing JavaScript tagged template literals at runtime, often with dynamic prop/theme interpolations:

```js
const Btn = styled.button`
  color: ${({ theme, primary }) => primary ? theme.colors.brand : theme.colors.muted};
`;
```

Static analysis can only see the template literal skeleton. Every `${...}` interpolation is opaque without a real React render cycle + live theme context. True support would require a component runner (a mini Storybook) that bundles the component, provides mock props/theme, and renders it for Playwright to scan — a separate subsystem, not a feature extension.

**Current behavior:** Both scanners detect CSS-in-JS imports and emit a warning:
- **Quick scan:** `▲ CSS-in-JS detected (<lib>) — contrast checking unavailable even with --full. Render to a static HTML snapshot for accurate results.`
- **Full scan:** `▲ CSS-in-JS detected (<lib>) — contrast checking unavailable. Render to a static HTML snapshot for accurate results.`

Scanning continues normally — all non-contrast violations (missing `alt`, unlabelled inputs, ARIA errors, etc.) are still reported. Only contrast checking is affected.

**Detected libraries:** `styled-components`, `@emotion/react`, `@emotion/styled`, `@emotion/css`, `styled-jsx/css`, `@stitches/react`

**Detection logic:** `detectCssInJs()` in `src/engine/transformers/transformerUtils.js`
**Fixtures:** `tests/samples/css-in-js/StyledComponentsTest.jsx`, `tests/samples/css-in-js/CssInJsExtraLibsTest.jsx`

## Implementation Notes

### Implementation Status

1. ✅ **Vue `<style>` / `<style scoped>` extraction** — `extractStyleBlocks()` in `vueTransformer.js` + `extraCssStrings` param in `resolvAndInjectCss()`
2. ✅ **Transitive `@import` in CSS files** — `extractTransitiveCssImports()` + recursive `loadCssFiles()` with O(1) visited-Set cycle guard
3. ✅ **Angular `styleUrls` + `styles[]`** — `extractStyleUrls()` + `extractInlineStyles()` in `angularTsExtractor.js`; wired in `fullScanner.js`
4. ✅ **`<link media="print">` filtering** — `media=["']print["']` guard added to the `extractCssLinkHrefs()` loop in `cssResolver.js`
5. ✅ **Custom alias resolution** — `loadTsconfigAliases()` reads `compilerOptions.paths` from `tsconfig.json` once per scan run; alias map threaded through `fullScanner.js` → `resolvAndInjectCss()` → `resolveOnePath()`
6. ✅ **CSS Modules — JSX/TSX** — `extractCssModuleBindings()` + `resolveCssModuleClass()` in `jsxTransformer.js`; default-import regex in `cssResolver.js`
7. ✅ **CSS Modules — Vue `<style module>`** — `tryExtractStyleModuleClass()` in `vueTransformer.js` resolves `$style['name']` and `$style.name`
8. ✅ **npm package CSS** — `resolveNodeModulesCss()` checks `<sourceDir>/node_modules/` then `<projectRoot>/node_modules/` (bare specifier with explicit subpath, e.g. `'bootstrap/dist/css/bootstrap.min.css'`)
9. ✅ **CSS Modules — Angular** — `extractCssModuleImports()` in `angularTsExtractor.js`; `transformAngularToHtml()` resolves `[class]="styles.prop"` / `[ngClass]="styles.prop"` (dot + bracket notation)
10. ❌ **CSS-in-JS** (`styled-components`, `@emotion/*`, `styled-jsx/css`, `@stitches/react`) — runtime-generated styles, out of scope; warning emitted per file

### npm CSS Test Fixture Design

Feature 8 (npm package CSS) uses a **locally committed fake npm package** — no real `npm install` needed:

```
tests/samples/npm-css/
  NpmCssTest.jsx                          ← imports 'test-fail-colors/fail.css'
  node_modules/
    test-fail-colors/
      fail.css                            ← contrast-failing CSS rules
```

The scanner resolves bare imports by checking `<sourceDir>/node_modules/` first. Since `NpmCssTest.jsx` lives in `tests/samples/npm-css/`, it automatically finds `tests/samples/npm-css/node_modules/test-fail-colors/fail.css`.

The test package is committed to git via a `.gitignore` exception:
```
node_modules/
!tests/samples/npm-css/node_modules/
!tests/samples/npm-css/node_modules/**
```
